# Agent Robot 通讯接入需求

## 1. 目标

在本机运行一个飞书机器人，使用户可以从手机飞书私聊机器人，向 Vidferry
Agent 发送任务请求并接收执行结果。机器人是现有 Agent 的远程受控入口，不是
第二套 Agent 系统。

首版实现完整的消息闭环：

```text
飞书手机客户端
  <-> 飞书自建应用机器人
  <-> 本地长连接通讯进程
  <-> Vidferry run_agent_chat
  <-> 飞书回复消息
```

## 2. 已确定的方案

| 项目 | 决策 |
| --- | --- |
| IM 平台 | 飞书 |
| 应用类型 | 企业自建应用，启用机器人能力 |
| 事件传输 | 飞书长连接，不开放本机公网 HTTP 端口 |
| 本地语言 | Python，复用 Vidferry 后端运行环境 |
| Agent 入口 | 复用 `app.core.agent_orchestrator.run_agent_chat` |
| 会话 | 一个飞书用户对应一个稳定的 Vidferry Agent session |
| 初始可用范围 | 仅白名单中的个人飞书用户私聊机器人 |
| 运行方式 | 首版手动启动；验证稳定后再单独设计 Windows 自启动 |

飞书官方长连接机器人示例：
https://open.feishu.cn/document/develop-an-echo-bot/explanation-of-example-code?lang=zh-CN

## 3. 功能范围

### 3.1 本阶段必须实现

1. 接收飞书私聊文本消息。
2. 验证发送者是否在允许用户白名单内。
3. 将文本、飞书用户标识和会话标识传给现有 `run_agent_chat`。
4. 向原消息回复 Agent 的最终文本结果和实际工具调用结果。
5. 在处理时间较长时先回复“已收到，正在处理”，最终结果以新消息或回复发回。
   工具结果中的项目目录图片可作为飞书图片消息发送；视频文件永不发送。
6. 记录请求 ID、飞书消息 ID、session ID、耗时和成功/失败状态；日志不得包含
   App Secret、API Key、Cookie、完整本地路径或原始敏感配置。
7. 提供健康检查/启动日志，明确显示机器人是否已建立飞书长连接。
8. 提供 `.env.example` 中的非敏感配置项说明，真实凭据仅保存在本机 `.env`。

### 3.2 明确不在本阶段实现

1. 新建或替换 Vidferry 的 Agent 推理、记忆、工具编排逻辑。
2. 自动下载、视频处理、修改配置、写数据库、发布平台内容或账号登录。
3. 文件上传下载、图片/语音消息、多用户群聊、定时任务和 Windows 服务自启动。
4. 个人微信非官方协议接入。

## 4. Agent 接入与权限边界

现有 Agent 已具备对话编排、会话记忆、安全策略与只读查询工具。飞书机器人必须
直接复用这些能力，并额外在 IM 入口做授权控制。

| 能力类别 | 首版状态 | 约束 |
| --- | --- | --- |
| 工作流、视频、账号、发布记录查询 | 允许 | 仅限白名单用户，沿用现有只读工具 |
| 文案建议、流程解释 | 允许 | 仅输出文本，不直接写入项目数据 |
| 下载、处理、配置修改、数据库写入 | 禁止 | 后续作为独立写操作工具设计 |
| 发布、上传、删除、登录 | 禁止 | 后续必须采用显式确认和最小权限授权 |

后续接入写操作时，每个工具都必须具备：

1. 独立白名单与参数校验，不根据自然语言直接执行任意命令。
2. 预览结果和影响范围；用户以确认口令确认后才执行。
3. 可审计的 request ID、操作者、参数摘要、结果和失败原因。
4. 发布、删除、账号登录等高风险操作要求单次确认，且不得由 Agent 自行确认。

## 5. 消息和会话约定

### 输入

- 只处理飞书私聊中的文本消息。
- 未授权用户收到固定拒绝回复，不进入 Agent，不泄露机器人配置。
- 空消息、非文本消息和重复事件直接忽略或返回简短提示。
- 同一飞书用户映射到一个内部 `session_id`，使跨手机消息可延续上下文。

### 输出

- Agent 的普通回答作为飞书文本消息返回。
- 输出继续经过现有敏感信息清理；机器人层不得拼接或回显环境变量。
- 超出飞书单条消息限制时按安全边界分段发送。
- 异常时只返回请求 ID 和通用失败说明，详细堆栈仅写本地日志。

## 6. 配置与密钥

新增配置使用 `.env`，并在 `.env.example` 中仅保留键名与无效示例值：

```env
FEISHU_APP_ID=cli_example
FEISHU_APP_SECRET=replace-me
FEISHU_ALLOWED_OPEN_IDS=ou_example
```

规则：

- `.env` 已由仓库忽略，禁止提交真实 App Secret。
- `FEISHU_ALLOWED_OPEN_IDS` 只填写允许与机器人私聊的飞书用户 Open ID。首次取值时可
  暂时留空启动机器人；此时所有消息都被拒绝，本地日志会显示发送者 Open ID，填入后重启。
- 不在终端、测试输出、日志或飞书消息中展示任何凭据。
- 应用凭据失效或长连接断开时，机器人进程必须给出明确但不泄密的错误。

## 7. 实施计划

1. 安装并锁定飞书官方 Python SDK，确认与现有 Python 环境兼容。
2. 新增独立的飞书通讯模块、配置读取模块和启动入口；不修改现有 HTTP Agent API
   的对外契约。
3. 实现长连接事件订阅、私聊文本过滤、用户白名单和事件幂等处理。
4. 实现飞书用户到 Vidferry session 的映射，以及 `run_agent_chat` 调用适配。
5. 实现处理中回执、最终回复、失败回复、输出分段和脱敏日志。
6. 增加单元测试：配置校验、授权拒绝、会话映射、消息解析、结果分段和异常处理。
7. 使用飞书测试应用进行手机端联调，并核对 Git 状态不包含 `.env` 或凭据。

## 8. 验收标准

1. 白名单用户在手机飞书发送一条文本，机器人能在本机日志中确认收到。
2. 该文本实际进入 `run_agent_chat`，而不是 Echo 或硬编码回复。
3. Agent 输出能回到同一条飞书会话，且可延续前一轮上下文。
4. 非白名单用户不能调用 Agent。
5. Agent 或飞书 API 失败时，机器人返回可追踪请求 ID，进程不退出。
6. `git status` 不显示 `.env`、密钥文件或生成的敏感日志。
7. 自动化测试通过，且不需要真实飞书凭据即可运行。

## 9. 用户需要提供的内容

实现前需要用户完成或确认以下事项：

1. 在飞书开发者后台创建测试自建应用，开启机器人能力和
   `im.message.receive_v1` 事件订阅，事件接收方式选择长连接。
2. 将 App ID、App Secret 写入本机 `.env`；不要通过聊天发送凭据。
3. 提供或确认用于白名单的飞书账号 Open ID。实现时可增加一条本地诊断命令帮助
   获取当前用户标识，标识不得写入仓库。
4. 确认机器人允许调用当前 Vidferry 的只读 Agent 功能。首版不包含任何写操作工具。

## 10. 后续阶段

在首版通讯闭环通过后，再逐项评审并实现下载、处理、文案落库、配置修改、平台
选择和发布工具。每类写操作单独定义权限、确认口令、审计字段、失败恢复策略和
测试，不因接入飞书而默认获得执行权限。
