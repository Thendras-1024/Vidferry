# 爆款视频分析实现说明

## 目的与边界

Vidferry 当前实现的是“候选视频传播潜力分析”，用于帮助用户从一批 YouTube 候选视频中选择更值得导入、处理的内容。它不是 YouTube 官方热榜数据，也不承诺某条视频一定成为爆款。

系统将判断拆成两个层次：

1. 候选检索阶段的公开元数据排序：成本低、速度快，用于初步筛选。
2. 用户确认后的音频字幕深度分析：只下载临时音频，使用 ASR 获取转写，再判断内容结构。

候选视频在被确认导入前不会自动下载完整视频、创建线索、处理或发布。

## 一、候选检索与去重

用户提出选题和筛选条件后，Agent 会调用 yt-dlp 搜索 YouTube。检索逻辑会：

1. 获取最多 50 条搜索摘要。
2. 过滤已经存在于本地 `youtube_videos` 表中的视频，避免反复推荐同一条视频。
3. 根据用户条件初筛，例如发布时间、播放量范围和时长范围。
4. 对最多 10 条候选补全详情元数据，最多并发 2 个请求，以降低触发 YouTube 429 的风险。
5. 将详情结果缓存 15 分钟，重复检索同一视频时不重复请求详情。

如果 YouTube 未返回播放量、发布时间或频道粉丝数，该视频仍可能保留在候选中，但元数据评分会降低，并提示“公开元数据不完整，热度判断置信度有限”。

## 二、同批热度：公开元数据排序

前端展示的“同批热度”只用于当前搜索结果的排序，不表示整个题材的市场热度。

评分范围为 0 至 100，由以下部分组成：

| 指标 | 上限 | 计算依据 |
| --- | ---: | --- |
| 播放速度 | 52 分 | `播放量 / 发布天数`，再按对数缩放 |
| 总播放量 | 20 分 | 播放量按对数缩放 |
| 新鲜度 | 18 分 | 发布时间越近，分数越高；约按 90 天指数衰减 |
| 相对频道表现 | 10 分 | `播放量 / 频道粉丝数`，播放量达到或超过粉丝数时表现更好 |

公式可概括为：

```text
同批热度 = min(100, 播放速度分 + 总播放量分 + 新鲜度分 + 相对频道表现分)
```

因此，分数较低通常不代表选题没有价值，可能只是：

- 该条视频发布时间较久，日均播放量变低；
- 题材本身较垂直，绝对播放量不高；
- 上传频道粉丝很多，播放量相对粉丝数并不突出；
- YouTube 当前未提供完整的播放量、发布时间或粉丝数。

界面悬浮提示会显示如“日均约 X 次播放”“发布约 X 天”“播放量相对频道粉丝数表现较好”等可解释信号。

## 三、音频字幕深度分析

当用户在候选列表中点击“深度分析所选 N 条”并确认后，系统才创建深度分析任务。默认限制如下：

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `CANDIDATE_ANALYSIS_MAX_ITEMS` | 3 | 单次最多分析 3 条候选 |
| `CANDIDATE_ANALYSIS_MAX_JOBS` | 1 | 同时运行的分析任务数 |
| `CANDIDATE_ANALYSIS_MAX_QUEUED_JOBS` | 2 | 等待队列上限 |
| `CANDIDATE_ANALYSIS_MAX_DURATION_SECONDS` | 1800 秒 | 单条视频最多 30 分钟 |

执行步骤：

```text
候选确认
  -> 下载最佳音频流（不下载完整视频）
  -> 提取适合 Whisper 的音频
  -> ASR 转写为带时间戳的字幕片段
  -> 删除临时音频
  -> 保存候选分析转写
  -> 规则分析 + 可选 LLM 分析
  -> 返回传播潜力分、依据、风险与可剪辑时间点
```

临时音频放在 `.runtime/candidate-analysis/`，转写结果保存在 `videos/transcripts/candidate-analysis/`。该流程不会创建媒体库视频记录，也不会把完整视频下载到 `videos/youtube/`。

## 四、内容结构评分

ASR 得到字幕后，系统先使用规则提取内容特征，生成 `contentScore`（0 至 100）：

| 维度 | 上限 | 当前判断方式 |
| --- | ---: | --- |
| 前 45 秒开场 | 40 分 | 检测提问、反差、结论、警告、秘密等中英文钩子词，以及开场文本长度 |
| 信息密度 | 25 分 | 每分钟有效转写字符数 |
| 叙事结构 | 20 分 | 检测“首先、然后、因为、但是、结果、总结”等连接词及其英文对应词 |
| 时长适配 | 15 分 | 10 分钟以内更适合当前短视频处理路径 |

系统还会输出：

- `hookExcerpt`：前 45 秒的字幕摘录；
- `reasons`：强开场、信息密度、叙事结构等依据；
- `risks`：有效语音过少、时长接近分析上限等风险；
- `confidence`：按有效转写字符数分为低、中、高。

## 五、可选 LLM 分析

当文本模型配置可用且 ASR 有有效转写时，系统会将字幕交给 LLM。LLM 仅能基于字幕内容生成：

- 中文摘要；
- 最多 3 条内容优势；
- 最多 3 条内容风险；
- 最多 3 个建议剪辑时间点及理由。

LLM 契约明确禁止编造画面、播放数据或保证爆款。若 LLM 调用失败，系统保留规则分析结果，不会使整个候选分析任务失败。

## 六、最终传播潜力分

深度分析完成后，最终分数为：

```text
传播潜力分 = round(同批热度 × 0.55 + 内容结构分 × 0.45)
```

其中：

- 同批热度反映已有公开传播表现；
- 内容结构分反映字幕中可识别的开场、密度和叙事信号；
- LLM 的摘要、优势、风险和剪辑点用于解释结果，不直接参与数值加分。

这个权重使系统不会只偏好“标题和播放量高”的旧视频，也不会仅凭字幕话术忽略真实的公开传播表现。

## 七、缓存、复用与状态

候选分析任务保存于 PostgreSQL 表 `candidate_analysis_jobs`，当前版本标识为 `candidate-v1`。

- 同一视频已经成功分析过：复用此前的转写和内容结构结果，只用当前候选的同批热度重新计算最终分数。
- 同一会话中同一视频正在分析：复用运行中的任务，不重复下载音频。
- 任务状态为：`queued`、`running`、`success`、`failed`。
- 前端每 3 秒轮询任务状态；记录不存在时停止更新，不再弹出错误提示。

## 八、当前限制与后续方向

当前实现的限制：

1. 只使用 YouTube 可取得的公开数据，没有评论互动率、完整推荐流曝光、完播率、点击率和受众画像。
2. 字幕无法可靠判断画面冲击力、镜头质量、封面质量、音乐节奏和人物表现。
3. 多语言 ASR 质量会直接影响内容结构判断。
4. YouTube 的反爬、Cookie、网络和元数据缺失会降低候选完整度。
5. 同批热度只能比较本次检索的候选，不能横向比较不同关键词、不同国家或不同时间段的全部内容。

可继续演进的方向：

- 引入同题材、同语言、同发布时间窗口的分位数归一化；
- 引入评论数、点赞数和互动率等公开指标；
- 对封面、首帧和镜头节奏做视觉分析；
- 持续记录导入、处理、发布后的真实表现，建立“候选特征 -> 发布效果”的项目内反馈模型；
- 将用户的目标平台、账号受众和历史发布表现加入排序。
