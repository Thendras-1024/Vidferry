# Vidferry Agent 能力路线图

## 已具备

| 能力 | Vidferry 落点 | 业务价值 |
| --- | --- | --- |
| 结构化工具调用与 ReAct 编排 | 视频、任务、账号、发布记录只读查询 | 根据实时业务数据回答，不把数据库事实写死在提示词中 |
| 会话记忆与上下文压缩 | 当前对话摘要、历史消息和会话锁 | 长对话可继续，避免上下文无限增长 |
| 安全策略与发布前质检 | 凭证脱敏、越权拦截、文本和视觉风险审核 | 发布前保留人工与规则控制点 |
| 多平台工作流 | 下载、转写、字幕、文案、发布队列 | 将 Agent 接入真实视频生产流程 |
| 运行诊断 | `get_agent_run_overview` | 可查询成功率、耗时、拦截和工具错误，不暴露历史正文 |

## 下一阶段

| 优先级 | 能力 | 与 Vidferry 的直接用途 | 验收指标 |
| --- | --- | --- | --- |
| P0 | 执行计划与当前轮确认 | 把下载、处理、发布变为计划预览、确认、幂等任务和状态回报 | 重复确认不重复创建发布任务 |
| P0 | Agent 回归评测集 | 固化视频查询、失败诊断、发布拒绝和提示注入用例 | 工具选择、任务完成、安全拦截、延迟四类指标可回归 |
| P1 | 视频知识检索 | 从字幕、内容分析和历史发布稿中定位高光、事实与风险提示 | 回答包含视频/字幕片段引用，避免无依据总结 |
| P1 | 人工修订反馈 | 用户修改标题、正文、标签后形成待确认偏好候选 | 候选未经确认不影响后续发布稿 |
| P2 | 多模型路由 | 视觉质检、文案生成、轻量查询按质量、延迟和成本选择模型 | 每类任务有质量、耗时和成本对比数据 |

## 不做

- 不为展示而增加多 Agent、向量数据库或外部记忆服务。
- 不让 Agent 直接执行 shell、SQL、浏览器脚本或平台发布。
- 不把 Cookie、API Key、账号文件、完整视频帧或原始历史对话写入诊断结果。

面试时可用该项目说明：先用只读工具和可审计运行记录建立可靠性基线，再将具备幂等与确认的高风险操作逐步开放给 Agent。
