# Vidferry 通用 Agent 意图识别与澄清平台需求文档

状态：需求草案

版本：v0.1

适用范围：Vidferry Web Agent 工作台与飞书机器人中的任务理解、能力路由、澄清、计划、确认、执行和审计。

## 1. 背景与目标

Vidferry 现有 Agent 已可通过受控工具查询视频、素材、账号和任务状态，并使用任务计划、提案确认和 SSE 向用户反馈处理过程。随着下载、处理、文案保存、发布及定时发布逐步接入，单纯依赖规则分支或通用 ReAct 循环，难以稳定回答以下问题：

- 用户想完成的业务目标是什么；
- 当前目标需要哪些能力、对象和前置条件；
- 信息不足时应向用户补充询问什么，而不是猜测并执行；
- 多个可行动作都合理时，如何让用户选择；
- 哪些动作可直接查询，哪些必须走计划和明确确认；
- Web 与飞书如何使用同一能力协议，同时保持会话和授权隔离。

本需求定义一个中心编排 Agent。它负责理解目标、约束、上下文与风险，按需调用四个受限业务专家 Skill，并统一生成可审计的意图结果。该平台的目标是提高业务路由的稳定性和可解释性，不是赋予模型更宽泛的执行权限。

## 2. 范围与非目标

### 2.1 本期范围

- 覆盖 Web Agent 工作台和飞书机器人两种入口。
- 支持采集发现、处理制作、内容发布、素材与运行诊断四类业务意图。
- 为缺失信息、歧义和多个合理操作提供结构化逐题澄清。
- 将所有写操作统一收敛到“固定提案、用户核对、明确确认、再次校验、幂等执行”的路径。
- 在现有 `agent_turn_events` 审计记录中补充意图路由和澄清事件。
- 通过灰度开关接入，并在异常时无副作用回退到当前规则与 ReAct 路径。

### 2.2 非目标

- 不引入专家间直接交接。所有专家均由中心编排 Agent 调用并返回结果。
- 不引入向量数据库、外部记忆服务、任意 Shell、任意 SQL 或任意浏览器能力。
- 不允许 Agent 直接写数据库、直接调用平台发布接口或自行提升权限。
- 不共享 Web 与飞书的会话历史、待确认项、澄清状态或用户上下文。
- 不以“置信度足够高”为理由跳过必填信息、提案确认、发布前质检或账号授权校验。
- 不在本需求实施阶段变更公共 API、数据库 schema 或飞书回调契约；这些变更须在实施前单独确认。

## 3. 设计原则

1. 意图、计划、工具调用和执行结果分层。意图回答“要做什么”，计划回答“如何做”，工具调用只执行当前一步。
2. 后端策略优先于模型判断。模型输出只能建议路由和参数，不能授予工具、跳过确认或绕过业务前置条件。
3. 信息不足时先澄清。未完成澄清前不得调用写工具、创建写操作提案或隐式补全风险参数。
4. 读写分离。查询和诊断可直接返回；下载、处理、保存文案、发布和定时发布必须进入受控提案链路。
5. 渠道隔离。Web 与飞书复用同一能力和卡片协议，但分别维护身份、会话、澄清和确认状态。
6. 失败默认保守。结构校验、授权、会话、卡片、参数或策略任一异常时，必须无副作用回退或要求用户重新发起。
7. 审计默认脱敏。事件只保留实现排障所需的匿名业务标识和结构化结果，不记录凭证、Cookie、密钥、绝对路径或未脱敏正文。

## 4. 总体架构

```text
Web 对话 / 飞书消息
  -> 渠道身份与会话边界校验
  -> 中心编排 Agent
      -> 规则、页面上下文、会话摘要和安全策略
      -> 意图结构化识别
      -> 澄清判断，或选择受限业务专家 Skill
  -> 后端工具注册表与业务策略
  -> 查询结果 / 澄清卡片 / 固定执行提案
  -> 用户选择或明确确认
  -> 再次校验、幂等执行、SSE 或飞书卡片反馈
  -> agent_turn_events 审计
```

中心编排 Agent 是唯一入口，负责以下工作：

- 提取业务目标、对象、约束、风险、当前上下文和完成条件；
- 判断请求是查询、规划、澄清、提案确认、取消还是状态追问；
- 选择一个主办专家，并在同一计划中按顺序调用其白名单能力；
- 判断是否存在缺失字段、多种合理操作或风险参数；
- 生成统一意图结果、澄清协议或现有兼容计划；
- 在工具或路由契约不满足时回退到既有路径，不执行副作用操作。

专家 Skill 不拥有独立会话、独立授权或写入权。它们只根据中心编排 Agent 传入的最小化上下文返回受限计划、参数建议和结果摘要。

## 5. 业务专家与工具边界

| 专家 | 负责范围 | 典型请求 | 允许能力 | 禁止事项 |
| --- | --- | --- | --- | --- |
| 采集发现 | 视频线索、频道、搜索、下载前筛选 | “找 5 条英文 AI 新闻视频” | 已注册的视频搜索、详情查询、下载前预览 | 直接下载、直接改写数据库、直接发布 |
| 处理制作 | 下载后的转写、翻译、字幕、烧录、剪辑和处理状态 | “给这个视频生成中英字幕” | 素材/任务查询、处理方案校验、处理提案生成、进度查询 | 跳过素材选择、跳过处理确认、直接执行 FFmpeg 或任意命令 |
| 内容发布 | 发布文案、预检、保存草稿、发布与定时发布 | “把这条发到小红书” | 文案与账号状态查询、文案和发布提案、现有预检调用 | 直接保存、直接发布、绕过账号/预检/确认 |
| 素材与运行诊断 | 素材库、账号、任务、失败原因和运行概览 | “为什么字幕任务失败了” | 素材、任务、账号、审计和诊断查询 | 读取 Cookie/密钥、直接修复配置、执行任意系统命令 |

工具注册表必须为每项能力声明：工具名、操作类型、风险等级、输入模式、输出模式、是否需要当前轮确认、业务前置条件、幂等键策略和超时上限。后端以注册表和业务策略为准，不能只依赖模型提示词。

跨专家的复合请求由中心编排 Agent 保持一个连续计划，例如“找视频后做字幕并准备发布”。在用户尚未选定视频、平台或处理方案时，先在必要节点澄清；不得让专家之间自行传递权限或直接接管对话。

## 6. 统一意图结果

### 6.1 结果结构

内部意图结果采用版本化结构 `agent-intent-v1`。建议字段如下：

```json
{
  "version": "agent-intent-v1",
  "intent": "prepare_publish_assets",
  "specialist": "content_publishing",
  "specialistLabel": "内容发布",
  "targetObjects": [
    { "type": "video", "id": "video_123" }
  ],
  "constraints": {
    "platform": "xiaohongshu",
    "language": "zh-CN"
  },
  "missingFields": ["publishTime"],
  "executionPlan": [],
  "riskLevel": "medium",
  "nextState": "needs_clarification"
}
```

字段语义：

| 字段 | 说明 |
| --- | --- |
| `version` | 协议版本，首版固定为 `agent-intent-v1`。 |
| `intent` | 规范化业务意图，例如 `discover_videos`、`process_media`、`publish_content`、`diagnose_run`。 |
| `specialist` | 主办专家的稳定标识，不作为用户可编辑权限。 |
| `targetObjects` | 仅保存视频、素材、账号、任务、发布稿等业务 ID 与类型，不保存本地绝对路径。 |
| `constraints` | 用户明确给出的平台、语言、数量、风格、时间等约束；未知值不伪造。 |
| `missingFields` | 继续执行或生成提案所需、但尚未获得的字段。 |
| `executionPlan` | 计划步骤的摘要；写操作计划不得成为执行凭证。 |
| `riskLevel` | `low`、`medium`、`high`、`critical`，由后端策略校正。 |
| `nextState` | `answer`、`needs_clarification`、`proposal_ready`、`waiting_confirmation`、`executing`、`completed`、`blocked` 或 `fallback`。 |

### 6.2 与现有响应的兼容

`taskPlan`、提案卡片、确认接口和既有 SSE 事件保持原有可用语义。意图结果为增量字段，不替代已有消费者已依赖的字段。

在未完成公共 API 契约评审前：

- 后端可先在内部运行记录和服务内对象中使用意图结果；
- `/agents/chat` 和 SSE 的新增字段必须可选、可忽略、带版本；
- 旧版 Web 页面和飞书只读路径必须能继续展示既有结果；
- 飞书交互回调中新增 `value` 结构前，必须单独确认签名、兼容与回滚方案。

## 7. 澄清协议与交互规则

### 7.1 触发条件

中心编排 Agent 遇到以下任一情况时，停止后续工具调用和写操作提案生成，进入澄清：

- 缺少执行所必需的对象、平台、账号、处理方案或时间；
- 用户输入对应多个合理动作，且现有上下文无法确定优先级；
- 一个对象有多个同样合理的匹配项；
- 风险等级要求由用户明确选择的参数；
- 解析结果、页面上下文和会话状态互相矛盾；
- 模型返回的意图或参数未通过结构、授权或业务前置校验。

仅当所有可行动作都是只读查询，且默认查询不会扩大数据范围时，才可在说明默认范围后直接返回结果。不能把“可能想下载、保存或发布”解释为用户已授权执行。

### 7.2 协议结构

澄清采用版本化结构 `agent-clarification-v1`。每次只返回当前一道题，用户完成该题后再根据新的上下文生成下一题。

```json
{
  "version": "agent-clarification-v1",
  "clarificationId": "opaque-id",
  "questionId": "target_platform",
  "field": "platform",
  "question": "这条内容准备发布到哪个平台？",
  "options": [
    {
      "id": "xiaohongshu",
      "label": "小红书",
      "description": "生成适合图文和短视频笔记的文案与话题。",
      "recommended": true
    }
  ],
  "current": 1,
  "total": 2,
  "canSkip": true,
  "expiresAt": "2026-08-21T12:00:00Z"
}
```

约束如下：

- `options` 必须为 2 至 4 个可理解、业务上合法的选项；不得把“其他”伪装成可执行默认值。
- 每个选项必须提供简短说明；仅可有一个 `recommended: true`。
- 推荐项必须来自明确业务策略、已有页面选择或当前上下文，不能仅因模型偏好生成。
- `current` 从 1 开始，`total` 是此轮已知的总题数；后续发现新的必填项时可以增加总题数，但必须重新返回完整进度。
- `clarificationId`、`questionId` 和选项 ID 均为服务端生成的短期令牌，不能由客户端拼装。
- 澄清有效期、会话绑定和使用次数由后端控制；过期、重复或跨会话提交必须拒绝并要求重新获取当前问题。

### 7.3 选择、跳过与关闭

- 选择一个选项后，后端校验身份、会话、问题、选项、有效期和当前业务前置条件，将选择写入当前会话的临时上下文，再恢复原计划。
- 一个请求需要多个字段时，以逐题形式推进，禁止一次展示一组彼此依赖的写操作参数。
- 用户选择“跳过”时，当前轮只允许返回查询结果、风险说明或下一步建议；不得生成下载、处理、保存文案、发布或定时发布的写操作提案。
- 用户关闭 Web 面板或关闭飞书卡片时，视为取消当前澄清，不修改业务数据，也不自动选择推荐项。
- 用户以自然语言补充信息时，应重新执行意图识别；若新信息可以回答当前题，则等价于一次有效选择，否则继续返回下一道澄清题。
- 用户后续主动重新发起写操作时，必须重新评估参数完整性和确认要求，不能复用已跳过的隐式授权。

### 7.4 Web 澄清面板

Web 使用嵌入 Agent 对话流的澄清面板，视觉和行为参考已确认的单题选择样式：

- 顶部显示当前问题、上一题/下一题状态、`当前题号 / 总题数`、关闭按钮。
- 选项按稳定序号纵向排列，整行可点击；每行展示编号、标题、说明、推荐标记和右侧箭头。
- 推荐标记只用于引导，不自动选中，也不能弱化其他选项的可见性。
- 底部单独提供“跳过”，并明确其仅返回查询结果或下一步建议。
- 每次选择后锁定当前题，显示提交状态，收到服务端响应后再展示下一题、计划或结果；重复点击不得重复提交。
- 窄屏中选项和操作区域自动换行，文本不得溢出或遮挡；关闭、跳过和选项均可键盘聚焦并具有可访问名称。

### 7.5 飞书澄清卡片

飞书使用与 Web 相同的 `agent-clarification-v1` 内容生成交互卡片：

- 卡片展示问题、进度、2 至 4 个选项说明、推荐标记和跳过动作。
- 每次交互只提交服务端生成的澄清令牌与选项 ID，不提交用户可伪造的完整计划或权限字段。
- 回调在恢复会话前必须重新校验飞书 `open_id`、机器人允许名单、渠道绑定、会话、澄清令牌、选项、有效期和业务前置条件。
- 选择后替换或追加下一张澄清卡、计划卡或结果卡；过期卡片返回“请重新发起”而不是尝试继续执行。
- 飞书卡片只复用能力协议，不读取或续接 Web 的上下文、待确认项或选择结果。

## 8. 计划、确认与执行边界

### 8.1 统一执行路径

导入、下载处理、保存文案、发布和定时发布必须遵循固定链路：

```text
后端固定提案
 -> 用户核对目标、参数、影响与风险
 -> 当前会话中的明确确认
 -> 再次校验身份、提案、前置条件与有效期
 -> 使用幂等键执行
 -> 返回任务或结果状态
```

要求：

- 提案必须由后端依据已校验业务数据生成，客户端和模型不能提交任意工具名或任意参数。
- 确认必须绑定当前渠道、当前用户、当前会话、提案版本和提案有效期；历史消息、记忆、推荐选项和澄清选择均不能当作写操作确认。
- 执行前重做账号状态、资源存在性、发布前质检、去重和业务前置检查。
- 幂等键覆盖网络重试、重复点击、重复飞书回调和重复确认，保证至多创建一个同类业务任务。
- 工具失败、过期确认或前置条件变化后不得自动降低风险或自动换用替代写操作；返回可理解的失败原因和可重新开始的建议。

### 8.2 状态机

```text
received
 -> routed
 -> needs_clarification
 -> planned
 -> waiting_confirmation
 -> executing
 -> completed / failed / cancelled

routed / needs_clarification / planned / waiting_confirmation
 -> fallback
```

`fallback` 仅表示新意图路由未被采用或已安全退出。它不能触发副作用，也不能覆盖旧路径已有的确认和安全策略。

## 9. 渠道、身份与会话隔离

Web 与飞书的会话必须以渠道和用户身份为边界隔离：

| 项目 | Web | 飞书 |
| --- | --- | --- |
| 身份来源 | 已登录 Vidferry 用户 | 已校验的飞书 `open_id` 与允许名单 |
| 会话范围 | Vidferry Web 会话 | 飞书机器人会话 |
| 澄清状态 | 仅当前 Web 会话可见 | 仅当前飞书会话和卡片可用 |
| 待确认提案 | 仅 Web 当前会话可确认 | 仅同一飞书身份和会话可确认 |
| 上下文复用 | 同渠道会话摘要与页面上下文 | 同渠道必要的会话上下文 |

禁止事项：

- 不允许在 Web 查看、确认或继续飞书发起的待处理操作。
- 不允许飞书卡片确认 Web 创建的提案。
- 不允许用共享的 App ID/App Secret 假设消息一定会路由到同一台机器或同一会话；运行部署仍需遵循当前飞书连接与允许名单策略。
- 不允许通过用户提供的会话 ID、卡片 ID 或业务对象 ID 跨越当前身份边界。

## 10. 审计、日志与隐私

### 10.1 `agent_turn_events` 事件

在既有 `agent_turn_events` 中追加以下事件类型，按一次用户请求的时间顺序写入：

| 事件 | 触发时机 | 最小记录内容 |
| --- | --- | --- |
| `agent_intent_routed` | 意图结构校验成功 | 协议版本、意图、专家、风险、匿名对象类型/数量、耗时 |
| `agent_clarification_requested` | 返回一道澄清题 | 字段、题号、总题数、选项 ID、可跳过、有效期摘要 |
| `agent_clarification_selected` | 用户选择有效选项 | 题目 ID、选项 ID、渠道、耗时 |
| `agent_clarification_skipped` | 用户跳过 | 题目 ID、渠道、后续状态 |
| `agent_clarification_rejected` | 令牌过期或校验失败 | 拒绝类别、渠道、原因码 |
| `agent_plan_created` | 后端生成计划或提案 | 计划版本、操作类别、风险、匿名目标标识 |
| `agent_confirmation_received` | 收到确认请求 | 提案版本、渠道、重复标记 |
| `agent_execution_started` | 幂等执行被接受 | 操作类别、幂等键摘要、任务标识摘要 |
| `agent_execution_finished` | 执行结束 | 成功/失败、错误类别、耗时、结果摘要 |
| `agent_intent_fallback` | 新路径安全回退 | 阶段、原因码、是否零副作用 |

### 10.2 数据最小化

事件、应用日志和诊断结果中禁止记录：

- Cookie、API Key、Token、密码、环境变量值和账号文件内容；
- 本地绝对路径、完整媒体文件名、完整转写、完整发布正文、完整工具原始响应；
- 未经脱敏的用户输入、飞书卡片回调原文和第三方错误正文。

记录业务对象时使用类型、短哈希或当前项目已有的匿名业务标识。日志文本遵循项目检索规范，例如 `agent intent routed : intent = publish_content , risk = medium`，在文本与标点、括号和符号之间保留空格。

## 11. 灰度、回退与差异评测

### 11.1 灰度开关

新增路由必须由默认关闭的灰度开关控制。开关的实际配置位置和名称在实施设计评审时确定，要求支持：

- 按环境、允许用户或渠道逐步启用；
- 在不重启现有服务的前提下按项目既有配置机制生效；
- 单独关闭 Web 或飞书入口；
- 出现契约异常时立即回到既有规则与 ReAct 路径。

### 11.2 回退规则

以下情况必须以零副作用方式回退：

- 意图结果不符合版本或字段约束；
- 专家、工具或参数不在注册表白名单中；
- 渠道身份、会话、澄清令牌或确认提案校验失败；
- 模型、结构化输出或专家调用超时、不可用或返回无法修复的错误；
- 新旧路由对于写操作的安全结论冲突。

回退仅能调用当前已存在的规则和 ReAct 路径，且仍受原有授权、确认、发布前质检和幂等保护。不得因灰度回退而双重执行工具。

### 11.3 灰度期对比

对启用灰度的请求，在不执行候选写工具的前提下记录新旧路径的差异：

- 业务意图、主办专家和风险等级；
- 工具白名单选择与预期顺序；
- 缺失字段和澄清结果；
- 是否会生成提案、是否需要确认；
- 最终状态、错误类别和耗时。

新增路由在关键安全用例上必须零绕过，整体评测结果不得低于现有基线路由，才可扩大灰度范围。

## 12. 验收与测试

### 12.1 专家场景

四个专家分别至少覆盖以下场景：

| 场景 | 必须验证的行为 |
| --- | --- |
| 明确请求 | 正确识别意图和专家，只调用该专家允许的只读能力或生成正确提案。 |
| 缺失字段 | 不调用写工具，不生成写提案，返回逐题澄清。 |
| 多意图 | 中心编排生成有序计划；对象或优先级不明确时先澄清。 |
| 歧义选择 | 选项数量为 2 至 4，说明、推荐、题号和总题数正确。 |
| 跳过 | 只返回查询结果或下一步建议，无写操作提案和执行。 |
| 工具失败 | 显示可理解失败，记录审计事件，不扩大工具权限或自动换用写操作。 |
| 提案确认 | 已确认提案经二次校验后仅执行一次。 |
| 重复确认 | 重复 Web 点击和重复飞书回调均不会创建重复任务。 |
| 过期卡片 | 过期选择和过期确认被拒绝，不恢复旧计划。 |

### 12.2 评测集

扩充现有 Agent 评测集，至少断言：

- 业务意图、主办专家、目标对象、约束和风险等级；
- Skill、工具、参数以及工具调用顺序；
- 澄清题、选项、推荐项、选择结果、跳过结果和状态变化；
- 工具白名单、确认边界、会话隔离、令牌校验和审计完整性；
- Cookie、密钥、绝对路径和未脱敏文本不进入模型诊断和事件记录；
- 发布、定时发布、删除、登录等关键安全用例不存在绕过。

### 12.3 协议与界面验证

- 验证 `/agents/chat`、SSE、既有 `taskPlan`、提案卡和确认响应的向后兼容。
- 验证 Web 单题澄清面板的进度、整行点击、推荐、关闭、跳过、提交中、过期和窄屏布局。
- 验证飞书卡片的内容映射、回调签名、身份绑定、重复回调、过期与异常回退。
- 验证 Web 与飞书无法相互读取、选择、确认或续接对方会话。
- 验证所有新增事件均有版本、耗时、匿名业务标识和结果，不含禁止落盘的数据。

### 12.4 实施完成时的最低验证

实施阶段应执行与改动匹配的 Python 测试、前端单测、`npm run build` 和 `git diff --check`。本需求文档本身不启动、停止或重启任何前端、后端、任务 Worker、浏览器会话或其他运行服务。
