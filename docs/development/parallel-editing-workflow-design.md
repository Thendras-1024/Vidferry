# 并行片头高光处理与局部更新

## 背景

处理版本二此前在字幕烧制完成后，会为拼接兼容性再次重编码完整正片。对于长视频，这一步会带来明显的额外耗时。

## 目标

- 正片字幕、水印、原作者信息只烧制一次，并保留为内部 `body` 文件。
- 高光审核完成后，从原视频与主 ASS 生成短高光和封面片头，与正片烧制并行。
- 最终仅以 FFmpeg concat `-c copy` 拼接封面、高光和 body，不再重编码完整正片。
- 文案重新生成与成片更新解耦；高光或封面建议变化时，保留旧成片并标记为“片头高光待更新”。

## 缓存与恢复

仅 `editing_v1` 使用 body、ASS、正片签名和片头签名。正片签名覆盖字幕及水印配置；片头签名覆盖封面和已选高光时间段。签名不匹配时不复用片头。

服务异常仍把运行任务标为异常，不自动续跑。用户重新发起处理会重新创建任务；已完成的 body 可用于“更新片头高光”，不会隐式复用旧任务的短片。删除或重置处理版本时会清理 body 与 ASS。

## 用户行为

- `处理`：没有匹配正片，或字幕/水印配置变化时执行完整处理。
- `更新片头高光`：正片仍匹配、但文案重新生成导致高光或封面变化时，仅重做封面和高光短片。
- `重新生成发布文案`：只复用转写缓存更新文案和高光建议；不会修改成片，而是将其标为待更新。

## 风险与边界

短片与正片固定使用相同分辨率、帧率、H.264/AAC 参数。若 FFmpeg concat 报告流不兼容，任务失败并保留 body，避免退化为再次重编码长正片。body 会额外占用一份正片磁盘空间，这是支持局部更新的必要代价。
