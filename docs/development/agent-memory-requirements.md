# Vidferry Agent 记忆与执行能力需求文档

状态：需求草案

版本：v0.1

适用范围：Vidferry 本地优先 Agent，包括对话、记忆、视频下载、视频处理、发布准备和多平台发布。

## 1. 背景与目标

Vidferry 当前 Agent 已具备只读查询、会话消息保存、运行记录和发布前质检能力。后续 Agent 将能够执行视频下载、字幕/剪辑处理、发布准备和平台发布等动作，因此需要同时解决以下问题：

1. Agent 能够记住当前会话正在处理的内容，并在上下文过长时压缩，而不是无限追加历史消息。
2. Agent 能够在用户明确确认后积累长期偏好，形成可查看、可编辑、可删除的人物画像。
3. 视频转写、完整发布稿、任务状态、账号状态等业务事实不复制到长期记忆；Agent 需要时通过受控工具实时查询。
4. 所有执行操作可预览、可确认、可取消、可追踪，发布和删除等高风险动作不能仅凭记忆或模型推断执行。
5. 用户可以按时间查看历史会话，主动删除会话；未删除的会话默认持续保留在本机数据库中。

## 2. 非目标

首版不做以下内容：

- 不引入向量数据库、知识图谱或外部记忆 SaaS。
- 不把完整转写、视频帧、完整发布稿和工具原始响应复制为长期记忆。
- 不根据聊天内容自动推断敏感身份、性格、年龄、性别、政治倾向或心理状态。
- 不让记忆系统覆盖安全策略、平台限制、账号权限或发布前质检结果。
- 不通过记忆保存 Cookie、API Key、Token、环境变量、绝对路径或平台登录材料。

## 3. 术语

- **工作记忆**：当前请求内的目标、工具结果和临时决策。
- **会话记忆**：一个 Agent 会话的最近消息、摘要和未完成事项。
- **情节记录**：历史对话、Agent 运行记录、工作流事件和发布记录。
- **语义记忆**：对未来仍然有用的稳定偏好、经验和项目知识。
- **程序记忆**：平台操作规则、内容流程和已确认的工作习惯。
- **运营者画像**：用户如何使用 Vidferry 的偏好。
- **内容画像**：用户希望制作的内容方向、受众和表达风格。
- **业务事实**：视频、字幕、素材、任务、账号和发布记录等由业务表维护的数据。

## 4. 总体原则

### 4.1 记忆与业务事实分离

Agent 需要视频详情、转写、发布稿或任务状态时，必须调用白名单工具读取业务表。记忆只保存查询线索、用户偏好、稳定经验和引用 ID，不保存业务事实的完整副本。

工具返回结果应提供紧凑摘要和引用信息，例如视频 ID、任务 ID、素材 ID；完整数据只在确实需要的步骤中读取。

### 4.2 显式偏好与自动候选分离

用户明确说“记住”或在界面确认的内容，才能成为正式的长期记忆。模型从用户修改、重复行为或工作流结果中推断出的内容，先保存为 `candidate`，不得直接影响后续执行。

### 4.3 安全约束优先于记忆

优先级固定为：

```text
代码级安全策略和平台限制
> 当前用户明确请求
> 用户确认的画像、规则和偏好
> 用户确认的长期记忆
> 自动生成的记忆候选
> 当前页面和一次性上下文
```

当前用户的明确请求可以覆盖普通风格偏好，但不能覆盖凭证保护、权限检查、发布前质检、危险动作确认等硬约束。

### 4.4 可见、可审计、可撤销

用户应能查看每条长期记忆的内容、类型、作用范围、来源、更新时间和置信度。记忆必须支持编辑、禁用、删除和恢复冲突处理。

## 5. 功能需求

### 5.1 会话管理与历史对话

#### 5.1.1 创建和继续会话

- 首次对话创建唯一 `session_id`。
- 前端可以继续当前会话，也可以新建会话。
- 会话标题默认使用首条用户消息的截断文本，允许用户修改。
- 会话需要记录创建时间、最后活动时间、消息数量、当前摘要版本和删除状态。

#### 5.1.2 历史会话列表

提供按时间浏览历史会话的能力：

- 默认按 `updated_at DESC` 排序。
- 支持按开始时间、结束时间筛选。
- 支持分页，避免一次性加载全部消息。
- 列表展示标题、创建时间、最后活动时间、消息数量和最近一次执行状态。
- 默认不提供全文内容预览，避免历史列表泄露过多文本。

建议接口：

```text
GET /agents/sessions?from=&to=&page=&pageSize=
GET /agents/sessions/:sessionId
GET /agents/sessions/:sessionId/messages?cursor=&limit=
PATCH /agents/sessions/:sessionId
DELETE /agents/sessions/:sessionId
```

#### 5.1.3 删除会话

- 删除操作必须由用户主动触发，并要求前端二次确认。
- 删除接口必须幂等。
- 删除会话时移除消息正文、页面上下文、工具响应正文、会话摘要和会话运行记录中的敏感输入。
- 已经由用户确认并独立存在的长期记忆不自动删除，但其来源标记为“已删除会话”。
- 未确认的记忆候选随会话删除。
- 后续可增加“删除会话并删除相关长期记忆”的增强选项，首版先保证默认删除行为清晰可控。

### 5.2 短期上下文与压缩记忆

#### 5.2.1 当前请求上下文

每次 Agent 请求最多包含：

- 用户当前问题；
- 当前页面和选中的视频、素材或任务引用；
- 当前会话摘要；
- 最近若干轮消息；
- 当前请求已经调用的工具摘要；
- 相关人物画像和长期记忆的少量结果。

完整工具响应不能无限写入上下文。工具必须支持字段裁剪、分页和数量上限。

#### 5.2.2 压缩触发

以下任一条件满足时触发会话压缩：

- 消息数量超过配置阈值；
- 字符数或估算 token 数超过上下文预算；
- 工具响应累计长度超过预算；
- Agent 开始执行新阶段，旧阶段细节不再必要。

压缩结果使用结构化摘要保存：

```text
goal              当前目标
decisions         已确认的决定
constraints       当前约束
referencedEntities 视频、任务、素材、平台等引用
pendingActions    未完成事项
userPreferencesObserved 观察到但尚未确认的偏好
```

压缩必须保留原始消息记录，摘要只是后续推理使用的上下文，不覆盖历史。

#### 5.2.3 摘要与长期记忆隔离

会话压缩摘要不是长期记忆。摘要中的“用户偏好”只能生成记忆候选，不能因为被写入摘要就自动升级为用户画像。

### 5.3 长期记忆

首版统一使用现有 `agent_memory_items` 表，并增加作用域、来源、状态、置信度和过期信息。

建议字段：

```text
memory_type       profile / preference / procedure / knowledge
scope_type        global / project / platform / channel / video / session
scope_id          作用域实体 ID
key               稳定键，例如 content.tone
content           人类可读内容
metadata          JSON 结构化值、标签和引用
source_type       user / model / workflow / system
source_session_id 来源会话
source_message_id 来源消息
status            candidate / active / rejected / superseded
explicit          是否用户明确确认
confidence        0-1 置信度
importance        重要程度
expires_at        过期时间
last_used_at      最近使用时间
created_at        创建时间
updated_at        更新时间
```

#### 5.3.1 记忆类型

- `profile`：运营者画像和内容画像。
- `preference`：标题、文案、字幕、话题和平台风格偏好。
- `procedure`：经过确认的工作流程习惯，例如“先生成预览再执行发布”。
- `knowledge`：稳定的项目知识或重复验证过的经验。

任务状态、视频转写、素材路径和发布记录不进入上述长期记忆，继续由业务工具读取。

#### 5.3.2 作用域和冲突

作用域从具体到宽泛依次为：会话、视频、平台/频道、项目、全局。

相同 `key` 存在冲突时：

- 当前用户明确要求优先；
- 更具体作用域优先；
- 用户确认优先于模型推断；
- 新内容不直接覆盖旧内容，先记录 `superseded` 或 `conflict` 关系；
- 无法自动判定时要求用户确认。

### 5.4 用户画像

#### 5.4.1 运营者画像

包括默认语言、常用平台、确认习惯、风险偏好、工作流偏好和常用操作顺序。

账号 Cookie、Token 和登录状态不属于画像；账号名称和平台映射应引用账号表或设置表。

#### 5.4.2 内容画像

包括目标受众、内容方向、叙事角度、标题风格、正文风格、标签偏好和禁用表达。

内容画像可以被内容分析和文案生成读取，但不能改变发布安全阈值或平台硬限制。

#### 5.4.3 画像生成时机

只有以下事件允许生成画像候选：

1. 用户明确使用“记住、以后都、默认、不要再”等表达。
2. 用户主动修改 Agent 生成的标题、正文、标签或处理方案。
3. 用户在同一偏好上连续出现至少两次一致行为，且跨越至少两个会话。
4. 用户确认一条自动生成的记忆候选。
5. 用户在设置页面直接填写画像字段。

单次聊天、单次点击、单次发布失败和模型自己的推断不能直接生成正式画像。

### 5.5 记忆提取与审批

记忆提取不应在每轮对话后无条件执行。推荐触发点：

- 用户明确要求记住或忘记；
- 用户完成一次文案或处理方案修改；
- 会话即将压缩；
- 会话结束或用户新建会话；
- 工作流完成并产生可重复的结果模式。

提取器必须输出结构化候选，至少包含：`type`、`scope`、`key`、`content`、`reason`、`confidence`、`sensitive`、`source`。

候选写入前必须执行：敏感信息脱敏、重复合并、冲突检测、作用域判断和内容长度限制。

用户在记忆页面可以：

- 接受候选；
- 修改后接受；
- 拒绝候选；
- 暂时禁用；
- 永久删除；
- 查看来源会话和最近使用记录。

### 5.6 业务工具按需读取

Agent 不应预先加载全部项目数据。工具按照意图分为：

| 工具类别 | 示例 | 是否修改数据 | 是否需要确认 |
|---|---|---:|---:|
| 查询 | 查询视频、转写、素材、任务、账号状态 | 否 | 否 |
| 规划 | 生成下载/处理/发布计划和预览 | 否 | 否 |
| 下载 | 创建视频下载任务 | 是 | 用户明确请求后确认 |
| 处理 | 创建转写、翻译、烧录或剪辑任务 | 是 | 用户明确请求后确认 |
| 发布准备 | 生成或修改发布稿、执行发布前质检 | 有限 | 修改前确认，质检自动执行 |
| 发布 | 提交平台发布任务 | 是 | 每次必须确认 |
| 删除/登录 | 删除素材、删除任务、账号登录 | 高风险 | 每次必须二次确认 |

模型只能调用工具白名单，不能直接执行任意 shell、SQL、浏览器脚本或平台命令。

工具执行返回 `action_id` 或 `job_id`，Agent 通过工具查询进度和结果，不把长日志直接塞入对话。

### 5.7 Agent 执行闭环

所有有副作用的操作必须遵循：

```text
理解请求
 -> 查询必要业务事实
 -> 生成执行计划
 -> 展示目标、参数、影响和风险
 -> 获取当前会话中的用户确认
 -> 创建幂等任务
 -> 返回 action_id/job_id
 -> 轮询或接收进度
 -> 汇报成功、失败或需要人工处理
```

确认不能来自历史记忆、画像、旧会话或模型推断。确认必须绑定当前会话、当前计划摘要和计划版本。

发布前仍必须经过现有文本/视觉质检；Agent 不能通过记忆跳过质检。

## 6. 风险边界

### 6.1 数据安全

- 长期记忆只保存本地 SQLite，不上传第三方记忆服务。
- 所有记忆和会话内容在进入 LLM 前执行敏感字段脱敏。
- 记忆内容、用户输入、转写和工具返回结果都视为不可信数据，使用明确区块传给模型。
- 日志和运行记录禁止保存 Cookie、API Key、Token、完整账号文件内容和完整视频帧 Base64。
- 删除会话后不应再通过历史接口返回消息正文或工具原始结果。

### 6.2 执行安全

- 查询工具默认只读。
- 下载和处理需要当前用户明确意图；Agent 不得从“帮我看看”推断为执行。
- 发布、删除、登录必须单独确认，不能与查询或计划确认合并。
- 高风险工具需要参数校验、账号状态检查、幂等键和超时处理。
- 任务失败时不能自动无限重试；重试必须有次数上限和用户可见原因。
- 发布失败、账号异常和视觉审核失败不能通过长期记忆自动放宽策略。

### 6.3 记忆安全

- 模型生成的候选默认无执行权限。
- 记忆不能携带工具调用指令、系统提示词或权限提升要求。
- 记忆冲突不能静默覆盖。
- 用户删除画像或记忆后，后续上下文不得继续注入该内容。
- 记忆提取失败不能阻塞视频下载、处理和发布任务。

## 7. 技术方案

### 7.1 复用现有技术

- 存储：继续使用 SQLite 和现有数据库初始化/迁移模式。
- 后端：Flask API、现有 `app/core/agent_memory.py`、`agent_orchestrator.py` 和工作流 Runner。
- LLM：复用 `call_json_contract`、现有中文提示词和结构化校验。
- 实时反馈：复用现有 SSE，增加执行状态事件。
- 前端：Vue 3、Pinia、Element Plus。
- 检索：首版使用 SQLite 条件过滤、作用域和关键词；需要时再启用 SQLite FTS5。

### 7.2 建议新增或拆分的模块

- `app/core/agent_memory.py`：记忆 CRUD、候选、审批、冲突、过期和脱敏。
- `app/core/agent_context.py`：会话历史、摘要、画像和相关记忆的上下文组装。
- `app/core/agent_execution.py`：计划、确认、幂等任务、取消和执行状态。
- `app/core/agent_tool_registry.py`：工具分类、参数模式、读写权限和确认级别。
- `app/api/agent.py`：会话历史、删除、记忆和执行确认接口。
- `sau_frontend/src/views/AgentHistory.vue`：历史会话列表和详情。
- `sau_frontend/src/views/AgentMemory.vue`：画像、记忆候选和长期记忆管理。

### 7.3 必要数据表调整

- `agent_sessions`：增加摘要、摘要版本、消息计数和 `deleted_at`。
- `agent_messages`：增加消息类型、序号/游标和删除策略需要的字段。
- `agent_memory_items`：增加作用域、来源、候选状态、置信度、过期和最近使用字段。
- `agent_runs`：记录计划、确认版本、执行结果和关联 `action_id/job_id`。
- 建议新增 `agent_action_logs`：记录工具名、脱敏参数、确认 ID、状态、错误和时间。

首版可以使用 `agent_memory_items.status = candidate` 表示候选，不必立即新建独立候选表。

## 8. 权限与确认模型

每个工具都必须声明：

```text
name
operation_type     read / plan / mutate
risk_level         low / medium / high / critical
required_confirm   none / current_turn / explicit_button
idempotency_key
input_schema
output_schema
timeout
```

Agent 的系统提示词只能描述能力边界；真正的权限和确认必须由后端工具注册表、策略检查和任务服务执行，不能只依赖模型自律。

## 9. 分阶段交付

### 阶段一：会话历史和短期记忆

- 历史会话列表、按时间筛选、详情和删除。
- 当前会话历史注入 Agent。
- 会话摘要和上下文压缩。
- 工具响应裁剪和引用化。

### 阶段二：显式画像和长期记忆

- 画像查看、编辑、删除。
- “记住/忘记”指令。
- 长期记忆 CRUD、来源和作用域。
- 记忆只读注入，不自动执行动作。

### 阶段三：执行计划与确认

- 下载、处理和发布工具分类。
- 计划预览、当前会话确认、取消、进度和失败恢复。
- `agent_action_logs` 和幂等任务。
- 发布前质检作为不可绕过的策略节点。

### 阶段四：自动记忆候选

- 从用户修正和重复行为提取候选。
- 候选审批、冲突、过期和回滚。
- 内容画像和平台偏好接入内容分析及发布稿生成。

### 阶段五：检索优化

- 统计记忆命中率、误用率和用户删除率。
- 只有在 SQLite 条件检索无法满足需求时才增加 FTS5。
- 暂不引入向量数据库。

## 10. 验收标准

1. 用户可以按时间查看所有未删除会话，并打开完整消息记录。
2. 用户删除会话后，历史接口不再返回该会话正文。
3. 当前会话过长时可以压缩，原始历史仍可查看。
4. Agent 查询视频、转写、任务和发布记录时通过工具按需读取。
5. 用户确认的偏好可以跨会话使用，且可以查看来源、编辑和删除。
6. 自动提取的偏好在用户确认前不会进入正式画像，也不会改变执行权限。
7. 下载、处理、发布等有副作用的操作都有计划、确认、任务 ID 和最终状态。
8. 发布、删除、登录不能通过历史确认、画像或长期记忆自动执行。
9. 记忆缺失、LLM 不可用或候选提取失败时，原有工作流仍可运行。
10. 测试覆盖会话删除、摘要压缩、记忆冲突、确认过期、重复执行和发布安全拦截。
