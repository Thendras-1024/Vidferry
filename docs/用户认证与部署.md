# 用户认证与部署

Vidferry 默认要求登录，不开放自助注册。系统只有 `admin` 和 `user` 两种固定角色，素材与发布任务属于同一受控工作区。

## 初始化管理员

完成 [快速部署](../QUICK_DEPLOYMENT.md) 的数据库配置后执行：

```powershell
conda run -n vidferry python -m app.auth.cli create-admin --username admin --display-name "管理员"
```

命令会交互式读取并确认密码。密码长度为 12 至 128 个字符，且不能包含用户名。已存在用户时命令会拒绝继续；管理员应在控制台“用户与安全”页面创建后续用户。

## 生产配置

在部署环境的安全变量或本地 `.env` 中设置：

```dotenv
VIDFERRY_AUTH_SECRET=<至少 48 字节的随机值>
VIDFERRY_AUTH_COOKIE_SECURE=true
VIDFERRY_AUTH_IDLE_MINUTES=480
VIDFERRY_AUTH_ABSOLUTE_HOURS=24
VIDFERRY_AUTH_REMEMBER_HOURS=168
VIDFERRY_AUTH_MAX_FAILURES=5
VIDFERRY_AUTH_LOCK_MINUTES=15
VIDFERRY_AUTH_ALLOW_COOKIE_EXPORT=false
```

可生成密钥：

```powershell
conda run -n vidferry python -c "import secrets; print(secrets.token_urlsafe(64))"
```

不要提交 `.env`，也不要把密钥、密码、会话 Cookie 或平台 Cookie 写入日志。

## 网络边界

- 使用 Caddy 或 Nginx 提供 HTTPS，并让前端与 API 使用同一受控域名。
- 后端默认只监听 `127.0.0.1:5409`，不要直接暴露该端口。
- HTTPS 环境必须设置 `VIDFERRY_AUTH_COOKIE_SECURE=true`；会话 Cookie 将使用 `__Host-vidferry_session`。
- 按实际前端域名配置 `VIDFERRY_CORS_ORIGINS`，不要使用通配符。
- 工作流调度和 SSE 包含进程内状态，生产环境保持单个后端进程。

## 权限与会话

普通用户可检索、处理和管理素材，也可创建发布任务；不能管理平台账号、Cookie、全局工作流设置或应用用户。管理员拥有这些管理权限。

平台 Cookie 导出默认对所有角色关闭。确需临时导出时设置 `VIDFERRY_AUTH_ALLOW_COOKIE_EXPORT=true`，完成后立即恢复 `false` 并检查审计记录。

- 管理员停用用户、重置密码或修改角色后，现有会话立即失效。
- 用户修改自己的密码后必须重新登录。
- 系统不能停用或降级最后一个有效管理员。
- 管理员可在“用户与安全”中解锁用户、撤销全部会话并查看审计日志。

备份应同时覆盖 PostgreSQL、`cookiesFile/` 和本地素材目录，并限制备份读取权限。
